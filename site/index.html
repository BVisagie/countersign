We left the cryptography to Bitwarden.

Countersign never encrypts your vault and never talks to Bitwarden's servers. The official CLI does both. We wrote the window, the keys and the cleanup.

  1. You press Enter in quick access.
  2. The app asks the daemon to copy. It sends an item id, never a secret.
  3. The daemon asks the official CLI over a private socket pair.
  4. The CLI decrypts the value and hands it to the daemon.
  5. The daemon puts it on the clipboard. The app never sees it.

  • No open portsThe CLI's server listens on no port and no path. Only the daemon holds the other end of its socket pair.
  • Secrets stay out of the appThe app gets item details with secrets removed. A secret arrives only when you reveal or edit it.
  • Checked downloadsCountersign installs the official CLI and checks it against a checksum recorded in its source.

It's early. Here's what isn't done.

Countersign is built and tested on Omarchy. An AUR package comes next.

  • Attachments and file Sends are built, but have only been tested against a free account, which refuses them.
  • Archived items need Premium to show. If Premium ends, they stay in the web vault until they're unarchived there.
  • The ARM build is built and tested on every release, but nobody has used it on Omarchy on ARM yet.
  • SSH keys can't be created, because the official CLI can't generate or import them.
